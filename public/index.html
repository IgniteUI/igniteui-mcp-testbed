How local skills work

A “skill” is just a folder with a SKILL.md inside (plus any files it references). opencode auto-loads every folder under the project’s .claude/skills/. You can drop in any skill you want — not only Ignite UI ones: a coding-style guide, a domain cheat-sheet, a “always write tests” rule, anything. The agent picks them up automatically.

Put each skill on the host under the matching framework folder (the selected platform is used for this run):

  • local-skills/angular/<your-skill>/SKILL.md
  • local-skills/react/…, local-skills/webcomponents/…, local-skills/blazor/…

When you enable Use local skills:

  • Merge (default): your local skills are copied on top of the generated ones. A local folder with the same name as a generated skill replaces it; new names are simply added.
  • Replace generated skills: the generated set is wiped first, so the agent sees only your local skills.

Folders without a SKILL.md are skipped. The line above lists what’s currently found for the selected framework.

Model

Local model? Prefix the id custom/<model> (e.g. custom/llama3.1), use host.containers.internal — not localhost — to reach the host, and put any non-empty API key. The server must bind 0.0.0.0.

Skill modes & local skills

Each variant row picks a skill mode, run against every selected platform:

  • No skills — agent runs with no skills.
  • Default skills — the generated Ignite UI skills only.
  • Local skills — only your skills (the generated set is wiped).
  • Default + local — generated skills with your local ones overlaid (same-named local folders replace generated ones; new names add).

Local skills are any folder with a SKILL.md you drop on the host under that platform — local-skills/<framework>/<your-skill>/. Each entry only uses its own platform’s folder. Add the same skill under several framework folders to compare them across platforms. The line above lists what’s found for the selected platforms when a row uses local skills.

    About provider packs

    A provider pack is a JSON file that teaches the testbed how to scaffold a project for a specific library, which MCP server to wire up, and where to fetch the agent skills. Pre-built pack files live in the 3rdPartyConfigurations/ folder of this repository.

    Once a pack is loaded it is persisted to the providers-data/ folder on the host (bind-mounted at /providers) and survives container restarts. Use the ✕ button to remove a pack.

    Container note: if a pack lists container dependencies (npm global packages), those must already be installed in the running image or the scaffold will fail at the configure step.
